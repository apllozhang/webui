# 提示词样例库 —— 如何让 AI 正确调用 ALE WebUI 规范

> 背景:6.0.0 发布后收到首个实战反馈——用 AI 把会议纪要转成 ALE 风格,结果没有 Logo、用了仿制方块。
> 根因不是 AI 能力,是**提示词没有给 AI 三样东西:真源位置、素材附件、验收方式**。
> ## 0. 交互式调用协议(给执行 AI 的行为规范——所有 AI 会话必须遵循)

当用户说"调用 WEBUI 工作 / 按 ALE 规范做 XX"而**未给出完整信息**时,禁止直接动手猜,必须先出示以下三个编号问题让用户确认,再按答案路由到对应模板:

> **问题 1 · 场景**:1) 独立文档(纪要/汇报/公告,单文件 HTML)  2) 业务页面(接入 kit 骨架)  3) 既有 ALE 页面增量修改  4) 试点仓库开发
> **问题 2 · 环境**:1) 有仓库/内网权限  2) 只有对话+附件(交付独立 HTML)  3) 需部署到内网服务器(8091/8095)
> **问题 3 · 版本与素材**:文档版本号?是否需要 ALE Logo?读者是 ALE 内部还是外发(决定 brand.md §2.4 授权分级)?

**路由表**:1+外发 → 模板一(附件 logo)+纯文字降级提醒;1+内部 → 模板一(附件 logo);2 → 模板二+design:check 验收;3 → 模板三+版本徽章自增;4 → 试点流程+release-lock 核验。
用户信息已完整时(给齐素材/环境/版本)可跳过提问直接执行;仍缺一样就问,不要猜。

下面三个模板按场景直接复制,把【】处填掉即可。核心原则:**给路径给素材,不给 AI 猜的机会。**

## 模板一:文档类(会议纪要 / 汇报页 / 公告页——独立单文件 HTML)

适用:不进代码仓库、单独发出去的 ALE 风格文档。**附件必须随提示词一并发**:本目录 `附件-ale-logo/` 里的两个 logo 文件(或告知素材目录路径)。

```text
你是 ALE WebUI 6.0.0 设计规范的执行者。请把【原始材料】改造成 ALE 风格的单文件 HTML,遵守以下硬性约束:

【品牌】
- 顶栏品牌区:使用附件 ale-logo.png(亮色主题)/ ale-logo-white.png(深色主题),高度 30px;
  亮暗切换跟随主题。禁止用 CSS 渐变+文字仿制 ALE Logo(商标,brand.md §2.4);
- 页脚加官方商标行:The Alcatel-Lucent name and logo are trademarks of Nokia
  used under license by ALE. www.al-enterprise.com

【设计令牌】(必须使用这些值,定义成 CSS 变量)
- 主紫 #6b489d / 深紫(标题)#4f3478 / 浅紫500 #7e5cb4 / 紫40 #e4d9f3 / 紫100 #f1ecf7
- 画布 #f7f7f5 / 表面 #ffffff / 正文 #1a1a1a / 次要文字 #4b4d50 / 弱文字 #616467
- 边框 #d9d9d6 / 柔和分隔 #e9e8e4;状态四色:bg+text 成对使用(info/success/warning/danger)
- 圆角 8/12/16px;字族 "Trebuchet MS","Noto Sans SC",sans-serif;顶栏底部 3px 主紫边

【结构】顶栏(logo+分隔线+文档标题+版本徽章) → 导航(锚点,aria-current) → hero(渐变紫+白色标题) → 内容分区(section-head 左紫线样式) → 页脚。
版本徽章:【vX.Y · YYYY-MM-DD】显示在顶栏,并与输出文件名一致。

【质量门槛】
- 320/768/1440 三档无横向溢出;对比度 ≥4.5:1;焦点可见;交互目标 ≥44px;
- 支持 prefers-reduced-motion(动画压到 0.01ms);亮暗双主题(跟随系统+手动切换);
- 图标按钮必须有 aria-label。

【交付】单文件 HTML(内联 CSS/JS),文件名:【文档名-vX.Y-YYYYMMDD.html】。
完成后自检:①双主题下 Logo 正确切换 ②三档无溢出 ③无未加载资源 ④徽章与文件名版本一致。
```

## 模板二:应用类(业务页面接入 kit 骨架——有仓库权限时)

适用:在内网/有 GitHub 权限的环境,为业务系统做 ALE 风格页面。**让 AI 先读仓库再动手**:

```text
你要基于 ALE WebUI 6.0.0 规范开发【页面描述】。工作目录:【仓库克隆路径】(或 github.com/apllozhang/webui)。

第一步(动手前必读,按顺序):
1. docs/START-HERE.md —— 上手与环境
2. docs/v6/00-foundations/brand.md §2 —— Logo 与授权分级
3. kit/tokens/*.json —— 令牌真源(改设计只改这里,禁止手改生成物)
4. 选择骨架:复杂系统用 kit/skeleton-react(React+TanStack);
   轻量页用 kit/skeleton-alpine;静态内容用 kit/skeleton-static

第二步(实现约束):
- 令牌一律引用 CSS 变量,禁止硬编码色值;新增色值须走 design-exceptions.yml 登记
- 组件优先复用骨架已有实现(数据表格/表单/抽屉/徽章);新组件遵守 docs/v6/20-components/ 对应条款
- 顶栏放版本徽章(运行时读 design-system.version.json,参照 spec-site 实现)

第三步(验收,全部通过才算完成):
cd kit/tools
npm run design:check        # 全量门禁(渲染/交互/320+768/字体双门禁)
npm run tokens:check && npm run rules:check
【如有试点】npm run pilot:tokens:check <路径> <项目名>
```

## 模板三:增量修改(已有 ALE 页面加内容/改样式)

```text
这是按 ALE WebUI 6.0.0 规范做的页面(附件)。请做以下修改:
【修改需求】
约束:
- 新增元素只用页面已有的 CSS 变量与组件类(btn/card/badge/table.data/section-head 等),不引入新框架;
- 新文字如需图标,用页面既有线性图标风格 + aria-label;
- 改动后:320px 无横向溢出、亮暗双主题正常、文件内版本徽章升【vX.(Y+1)】并与文件名同步。
```

## 为什么模板要这样写(失败案例对照)

| 不给 AI 什么 | 会发生什么(实际案例) |
|---|---|
| Logo 素材与来源规则 | AI 造渐变方块仿制 Logo(违反 brand.md §2.1/§2.4) |
| 令牌具体值 | AI 用自己的审美色(蓝渐变/微软雅黑) |
| 版本徽章要求 | 无版本标识,文件无法区分迭代 |
| 验收方式 | AI 说"完成了"但 320 溢出/对比度不足 |

一句话:**令牌、素材、验收,三样给齐,AI 就是规范执行者;缺一样,它就是自由发挥者。**
