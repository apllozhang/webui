## 一、整改清单

### R11(续办)React 1440 filler 空白列
评估方实测 396px、占表格 34.4%(比移交方"约30%"更精确,以此为准)。修复方向仍按验收结论 §四二选一:未进入精确模式时按策略分配余量(如标题列弹性拉伸),或 filler 视觉中性化。DoD 不变:1440 视觉连续、F14/320/门禁不回归。

### R12(P1)Alpine 主题双绑定修复
- 根因(以移交方插桩结论为准):Alpine init() 命名约定 + 显式 `x-init="init()"` 双重调用 `demoApp().init()`,theme.js 无幂等保护。
- 修复:①去掉 index.html 中冗余的 `x-init="init()"`(main 与 formDemo 两处,依赖 Alpine 约定自动调用);②`theme.js init()` 增加幂等标记(`if (this._inited) return`);③排查 Hub 与其他入口是否存在同型双重初始化,一并清理。
- DoD:线上 `/alpine/` 主题按钮单击即切换(dark↔light 各验证一次),`localStorage.theme` 与 `.dark` class 同步;R18 交互门禁含此断言。

### R13(P1)React 表单"必选同意"纳入提交校验
- 现象:FormsDemo 未勾选"我已阅读并同意条款(必选)"仍创建成功(`submit()` 只检查 name)。
- 修复:`agree` 纳入校验与错误摘要(ErrorSummary 已自带聚焦);失败不发成功 Toast。
- DoD:未勾选提交 → 出现同意项错误、无成功 Toast、焦点落在错误摘要;勾选后正常创建。

### R14(P1)React 表单错误 ARIA 关联
- 现象:`fieldAria()` 在 Field.tsx:25 定义但全仓库零调用;`#demo-name` 无 `aria-invalid`/`aria-describedby`/`aria-required`,违反 docs/v6/20-components/form.md。
- 修复:Field 组件通过 cloneElement/render-prop 自动注入 ARIA 到 child input(不让调用端记得手动传);FormsDemo 生效。
- DoD:空表单提交后,输入框 `aria-invalid=true`、`aria-describedby` 指向 help+error ID、必填 `aria-required=true`;规范条款与实现一致。

### R15(P1)AppShell 移动抽屉焦点圈闭/归还
- 现象:AppShell 移动导航抽屉仅实现 Esc 关闭,无打开聚焦、Tab 圈闭、关闭归还,违反 docs/v6/20-components/app-shell.md。
- 修复:复用仓库内 Drawer/Dialog 的焦点陷阱模式(feedback/index.tsx FB-FOCUS-001)。
- DoD:320px 打开抽屉后焦点入圈,Tab/Shift+Tab 循环不出圈,关闭后焦点归还触发按钮。

### R16(P1)Static 面包屑修复 + 子路径导航回归
- 现象:article.html:5 `href="/"` 点击"首页"跳出 Static 到 Kit Hub。
- 修复:改为相对入口(`index.html`)或构建配置 base;排查全部模板同类绝对引用。
- DoD:文章页面包屑"首页"落在 Static 首页;R18 门禁含目的地断言。

### R17(P2,门禁诚实性)对比度报告三分类输出
- 现象:输出含 SKIP/EXEMPT 却总述"ALL PASS";其中 2 个 SKIP 的原因是 **dark/on-action 与 on-action-hover 令牌值缺失**——核心交互角色缺值不应静默跳过。
- 修复:①补齐 dark 主题 on-action/on-action-hover 令牌值并纳入断言(补值后须过 4.5:1,否则调色并全链同步);②contrast-check 输出改为三分类计数:`X PASS / Y EXEMPT(关联规则 ID) / Z SKIP(须为零,非零即 FAIL)`;③EXEMPT 项登记规则出处(15 章附录 G);④全仓库禁用"46 对 ALL PASS"类表述,以实际分类计数为准。
- DoD:`npm run tokens:contrast` 输出三分类、SKIP=0;docs 与报告中的历史表述已修正。

### R18(P1,防复发)交互门禁:从"页面存在"到"行为正确"
- 现象:本轮 N1–N5 在 32/32 门禁全绿时并存——门禁只查渲染/资产/控制台/溢出,不查交互。
- 修复:check-kit.mjs 新增交互断言(评估方建议,移交方采纳为本轮必改):①逐入口主题按钮单击切换断言(本轮 N1 回归);②React 表单必选同意提交契约(N2 回归);③AppShell 抽屉 Tab 圈闭抽查(N4 回归);④Static 面包屑目的地断言(N5 回归)。
- DoD:上述断言进 `design:check` 一条命令;故意注入任一回归(如还原双绑定)时门禁变红(自测一次并记录)。
