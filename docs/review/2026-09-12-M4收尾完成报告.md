## 1. 各项明细

### 1.1 CI 化（含三次排障记录，供 §8 教训表参考）

`design-gate.yml`：push(main) 与 workflow_dispatch 触发，跑 **tokens:check（零漂移）→ tokens:contrast（46 对断言）→ design:check（12 项浏览器门禁，对 runner 本地起场的 spec-site）**；artifact 上传保留 14 天；运行结论回写 `.github/ci-state.json`（`[skip ci]` 防循环）——私有仓库无 API token 时，**git log 即运行台账**。

排障三轮（前 6 次红叉的完整解释，避免误读为"门禁有问题"）：

| 迭代 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 报告步骤推不回 | workflow 级 `contents: read` 使 GITHUB_TOKEN 只读 | 提权 `contents: write`（`0db7002`） |
| 2 | 仍推不回（exit 128） | Actions checkout 是 detached HEAD，本地无 `main` 分支，`git push origin main` 报 refspec 错 | `git push origin HEAD:refs/heads/main`（`4e71296`） |
| 3 | RC=1（由 Run Summary 日志确诊） | **门禁运行会重写被跟踪的 artifact 文件 → 工作区带未暂存改动 → rebase 拒绝执行**（`cannot rebase: You have unstaged changes`） | commit 后 `git checkout -- .` 丢弃 artifact 改动再 rebase（`e9d93ac`） |

经验沉淀：Actions `run` 默认 `bash -e`，任何未保护的 git 失败即刻杀死步骤；把回写步骤改为 `set +e` + 全量捕获 + 写入 `$GITHUB_STEP_SUMMARY`（运行页可直接看到结论与原始 git 输出），步骤本身永不红——**红不红只由三道门禁决定**。

### 1.2 示例库（四链路 ✅/❌ 对照）

每链路一组代码级对照，均含"为什么错"与规范出处，文案刻意避开规则关键词以免被扫描器误登记为条款：

- **app-shell**：面包屑表层级（`aria-current`）vs 步骤条伪装成面包屑（多步流程应走 `10-patterns/wizard-flow.md` 的 Stepper）；
- **data-table**：状态"圆点+文字"双编码徽章 vs 纯色点（色彩不单独传达状态）；数字列 `tabular-nums` 右对齐；
- **form**：字段级错误（`aria-invalid` + `aria-describedby` + role=alert 说明"问题+修复方法"）vs 红框无说明 + placeholder 当标签 + 错误只进 Toast；只读用文本而非 `disabled` 伪装；
- **feedback**：Dialog 确认 → 服务端成功 → Toast(role=status) → 列表刷新 的破坏性操作链 vs `window.alert()` / 只 Toast 不刷新 / 表单错误用 Toast；Skeleton 是结构占位不是加载动画替身。
