## 发现：F-NEW-1（P1，非阻塞，移交接手方修复）

**现象**：在 `core.autocrlf=true` 的 Windows 工作副本上，`npm run rules:check` 报 23 个文件 DRIFT；同一命令在 CI（Linux/LF）为绿。

**根因**：`scan-rules.mjs` 读文件后直接 `raw.split("\n")`，未规范化 CRLF——autocrlf 检出为 CRLF 时每行尾带 `\r`，与 LF 生成的注册表比对必漂移。若在此环境跑 `rules:build`（非 check），会重写全部 31 个 md 的 EOL（内容不丢但产生巨型噪声提交）。

**修法（一行级）**：`parseFile` 中 `const raw = fs.readFileSync(file, "utf8").replace(/\r\n/g, "\n");`，重建写回统一 LF；可选：仓库加 `.gitattributes`（`*.md text eol=lf`）根治。

**裁定**：不阻塞 M4 验收（CI 环境门禁真实有效），但属**门禁可移植性缺口**——建议接手方在开工 M5 前修复并补一条教训入 §8 教训表。
