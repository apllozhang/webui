### R2-N1　Alpine 主题切换一次点击执行两次

- 严重级：P1
- 状态：**新发现**
- 证据：`[data-theme-toggle]` 实测有 2 个 click listener；一次点击后 MutationObserver 记录 root 先加入 `dark`，随后又移除，最终 `localStorage.theme=light`、背景仍为亮色。320/1440 结果一致。
- 根因：`kit/skeleton-alpine/index.html` 在主区 `x-init="init()"` 调用 `ALETheme.init()`，另一表单区 `x-init="init()"` 又调用同名初始化逻辑；共享脚本的 `Theme.init()` 没有幂等保护。
- 证据文件：`evidence-round2-3ad63fd/supplemental.json`、`alpine-theme-click.png`。
- 修复建议：主题初始化只放在应用根节点；同时给 `Theme.init()` 增加幂等标记，防止未来多模块重复绑定。新增点击后 `.dark` 与 localStorage 同步的交互门禁。

### R2-N2　React 表单“必选同意”未参与提交校验

- 严重级：P1
- 状态：**新发现**
- 证据：在 `/react/#/forms` 输入合法名称、保持“我已阅读并同意条款（必选）”未勾选，点击“创建”后仍出现“已创建：独立评估临时输入”。`FormsDemo.tsx` 保存了 `agree` 状态，但 `submit()` 只检查 `name`。
- 截图：`evidence-round2-3ad63fd/react-form-unchecked-320.png`、`react-form-unchecked-1440.png`。
- 影响：示例向使用者展示错误的必填与提交契约，可能被真实项目照搬。
- 修复建议：把 agree 纳入全量校验和错误摘要；失败时不发成功 Toast，并把焦点移到错误摘要或首个错误字段。

### R2-N3　React 表单错误没有关联到输入控件

- 严重级：P1
- 状态：**新发现**
- 证据：空表单提交后页面出现 `#demo-name-error` 和“请输入名称”，但 `#demo-name` 的 `aria-invalid`、`aria-describedby`、`aria-required`、HTML `required` 均为空/false。`Field.tsx` 生成了错误 ID，但没有把属性注入 child；`FormsDemo.tsx` 也未调用已提供的 `fieldAria()`。
- 规范冲突：`docs/v6/20-components/form.md` 要求 Label 显式关联、错误与帮助经 `aria-describedby` 关联、必填使用 `aria-required`。
- 证据文件：`evidence-round2-3ad63fd/supplemental.json`、`react-form-error-320.png`。
- 修复建议：让 Field 通过 render prop/context 或 `cloneElement` 显式注入 ARIA，或要求调用端使用 `fieldAria()`并由测试强制验证。

### R2-N4　React 移动抽屉未实现文档声明的焦点圈闭/归还

- 严重级：P1
- 状态：**新发现**
- 证据：320px 打开导航抽屉后，焦点仍停留在抽屉外的 FAB；从抽屉最后链接按 Tab，焦点移到抽屉外。源码 `AppShell.tsx` 只实现 Esc 关闭，没有打开时聚焦、Tab 圈闭和关闭后焦点归还。
- 规范冲突：`docs/v6/20-components/app-shell.md` 明确要求“抽屉焦点圈闭/归还”。
- 证据文件：`evidence-round2-3ad63fd/supplemental.json`、`react-menu-focus-320.png`。
- 修复建议：使用 dialog/focus-trap 机制；打开后聚焦首项，Tab/Shift+Tab 循环，Esc 或导航后关闭并把焦点归还触发按钮。

### R2-N5　Static 文章面包屑“首页”跳出 Static 工程档
