# ALE WebUI 设计与实现指导规范

**版本：v4.1（通用版）**  
**适用对象：** ALE 品牌下的门户、知识库、内容站点、业务系统、工作台、管理后台及数据应用  
**目标：** 在不同产品、业务和技术栈中，稳定复用 ALE 的品牌识别、界面气质、交互规则和工程实现方式。

---

## 0. 文档定位与使用原则

本规范不是某个现有系统的界面复刻说明，也不预设具体业务模型。它定义一套可跨项目复用的 ALE WebUI 语言。

设计和开发按以下优先级处理冲突：

1. **官方品牌规则**：Logo、品牌名称、官方色、字体、影像和法律声明。
2. **本规范的 Web 规则**：无障碍、响应式、设计令牌、组件状态和工程约束。
3. **项目级主题**：在不破坏前两层的前提下，增加少量业务语义和组件。
4. **参考实现**：TSSKB 可用于理解一种 ALE 风格的落地方式，但不等于官方品牌规范，也不决定其他项目的业务结构。

### 0.1 规范强度

- **必须**：涉及品牌正确性、无障碍、基础交互一致性或高风险误操作。
- **建议**：默认应采用；若偏离，应在设计评审中说明原因。
- **可选**：按内容密度、使用场景和技术条件决定。

### 0.2 通用化原则

- 示例只使用内容、课程、用户、任务、服务、记录、报表等中性对象。
- 组件规则描述行为和信息层级，不绑定具体行业字段。
- 图表表达通用指标，不预设指标含义和单位。
- 技术示例以标准 HTML/CSS 为基线，不把某个框架写成品牌要求。

# 第一部分：品牌基础

## 1. ALE WebUI 的设计气质

- **清晰**：信息层级明确，用户一眼能找到页面目标和下一步动作。
- **可信**：颜色克制、排版稳定、反馈准确，不用夸张装饰制造科技感。
- **开放**：留白充足、结构轻盈，避免封闭、拥挤和过度面板化。
- **高效**：常用操作靠近内容，复杂任务分步完成，错误可恢复。
- **有品牌辨识度**：以 ALE Purple、正确 Logo、左对齐排版和少量品牌色建立识别，而不是把整个页面染成紫色。

品牌感优先级：

> Logo 与命名正确 > 信息结构清晰 > 紫色用于关键动作 > 细节装饰

## 2. Logo、名称与法律信息

### 2.1 Logo 使用

- 浅色背景优先使用标准彩色 Logo。
- 深色或品牌色背景使用官方白色反白版本。
- 不重绘、不拉伸、不倾斜、不裁切、不改变比例。
- 不自行改色，不添加描边、阴影、发光、渐变或动画特效。
- Logo 周围保留官方安全空间；文字、按钮、分隔线或其他标识不得侵入。
- 与合作方 Logo 并列时，遵守官方规定的安全距离和视觉尺寸关系。
- 禁止用文本或自行绘制的图形替代正式 Logo 文件。
- 量化硬规则（最小净空、透明区、禁用样式与资产来源）见附录 D。

### 2.2 品牌名称

- 页面首次正式出现公司名称时，写作 **Alcatel-Lucent Enterprise**。
- 后续可使用 **ALE**。
- 不使用可能造成品牌主体混淆的非正式简称。

### 2.3 法律与商标

面向外部或正式发布的品牌网站，应在页脚、Legal 或 About 页面提供经法务确认的版权、商标和法律声明。不要从旧项目复制可能已过期的声明。
官方推荐文本与版权行格式见附录 D.4；引用前以品牌指南最新发布版复核。

## 3. 色彩系统

### 3.1 官方品牌色与 Web 派生色

官方品牌色是品牌资产；Web 派生色用于满足状态、对比度和交互需要。两者必须在命名上分开。

| 官方基础色 | 色值 | 推荐用途 |
|---|---:|---|
| ALE Purple | `#6B489D` | 品牌识别、主按钮、重点链接、选中态 |
| Black | `#000000` | 品牌资产或特殊高对比场景 |
| White | `#FFFFFF` | 主背景、反白内容 |

官方扩展色可按品牌指南使用，例如蓝、青、绿、橙、红和灰阶，但不应无目的地同时出现。
官方色板为每个色相提供 100%/80%/60%/40%/20% 五档色调；Web 语义色需要变体（悬停、浅底、边框）时只从这五档取值，不发明新色（见附录 D.1）。

| Web 语义 | 建议值 | 用途 |
|---|---:|---|
| `color-action-primary` | `#6B489D` | 主动作背景、选中态 |
| `color-action-primary-hover` | `#4F3478` | 主动作悬停和按下态 |
| `color-link` | `#006AA2` | 白底小号正文链接 |
| `color-success` | `#007A73` | 成功文字、图标、边框 |
| `color-warning` | `#9A4707` | 警告文字、图标、边框 |
| `color-danger` | `#A50034` | 错误和危险操作 |
| `color-info` | `#006AA2` | 信息提示 |
| `color-text-primary` | `#1A1A1A` | 主正文和标题 |
| `color-text-secondary` | `#4B4D50` | 次级信息 |
| `color-text-muted` | `#616467` | 辅助信息 |
| `color-border` | `#D9D9D6` | 边框和分隔线 |
| `color-surface` | `#FFFFFF` | 卡片、弹层、控件背景 |
| `color-canvas` | `#F6F6F4` | 应用画布背景 |

官方亮色不一定适合直接作为白底小字号文字。例如 `#0085CA`、`#00B2A9`、`#FF4500` 在白底上不满足普通正文所需的 4.5:1 对比度，应改用于较大图形、装饰块，或使用表中的深色 Web 派生值。

### 3.2 色彩比例和语义

建议默认比例：

- 中性色和白色：约 75%–85%
- ALE Purple：约 10%–15%
- 状态色和辅助色：通常不超过 10%

颜色不得单独传达成功、警告、失败、选中或禁用状态，必须再提供文本、图标、形状、边框或位置线索。

## 4. 字体与排版

### 4.1 字体栈

ALE 官方品牌指南以 Trebuchet MS 为主要系统字体，并提供 Noto Sans 作为辅助选择。

```css
font-family: "Trebuchet MS", "Noto Sans SC", "Microsoft YaHei UI",
  "PingFang SC", "Segoe UI", Arial, sans-serif;
```

代码和等宽内容：

```css
font-family: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

### 4.2 字号与行高

| 角色 | 桌面端 | 小屏端 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 32px | 26px | 1.2 |
| 区块标题 | 24px | 21px | 1.25 |
| 三级标题 | 19px | 18px | 1.35 |
| 正文 | 16px | 16px | 1.65 |
| 紧凑控件文字 | 14px | 14px | 1.45 |
| 辅助文字 | 13px | 13px | 1.45 |

正文默认 16px。只有表格、标签、元数据和高密度控件可降至 14px；13px 或更小字号不得承载核心任务信息。

### 4.3 排版规则

- 标题和正文默认左对齐。
- 每行正文建议控制在 60–80 个中文字符或 65–85 个拉丁字符。
- 标题依层级顺序使用，不能仅为视觉大小跳级。
- 段落间距应大于行间距。
- 大写字母、斜体和全粗体段落应少用。
- 文章型页面可给二级标题增加紫色左标；应用型页面不应机械重复该装饰。

## 5. 图像与图标

- 图片真实、自然、清晰，避免低分辨率和过度滤镜。
- 裁切保留主体，不让文字覆盖关键信息。
- 内容图片有合适 `alt`；纯装饰图片使用空 `alt=""`。
- 不把重要文字只放在图片中。
- 同一产品使用一套图标家族，默认线性图标，常用尺寸为 16、18、20、24px。
- 图标按钮必须提供可访问名称，例如 `aria-label="关闭"`；`title` 只能作为补充。
- 品牌 Logo 与功能图标是两类资产，不能混用。

# 第二部分：设计令牌与页面结构

## 6. 三层设计令牌

令牌按基础值、语义用途、组件变量组织，避免在组件中散落颜色和任意尺寸。

```css
:root {
  /* Primitive */
  --ale-purple-600: #6b489d;
  --ale-purple-800: #4f3478;
  --neutral-0: #ffffff;
  --neutral-50: #f6f6f4;
  --neutral-200: #d9d9d6;
  --neutral-500: #616467;
  --neutral-700: #4b4d50;
  --neutral-950: #1a1a1a;

  /* Semantic */
  --color-canvas: var(--neutral-50);
  --color-surface: var(--neutral-0);
  --color-text-primary: var(--neutral-950);
  --color-text-secondary: var(--neutral-700);
  --color-text-muted: var(--neutral-500);
  --color-border: var(--neutral-200);
  --color-action: var(--ale-purple-600);
  --color-action-hover: var(--ale-purple-800);

  /* Component */
  --button-primary-bg: var(--color-action);
  --button-primary-bg-hover: var(--color-action-hover);
  --input-border: var(--color-border);
  --card-bg: var(--color-surface);

  --radius-sm: 6px;
  --radius-md: 10px;
  --radius-lg: 16px;
  --shadow-sm: 0 1px 3px rgb(0 0 0 / 8%);
  --shadow-md: 0 8px 24px rgb(0 0 0 / 12%);
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 24px;
  --space-6: 32px;
  --space-7: 48px;
  --content-max: 1180px;
}
```

项目可以扩展语义令牌，但不得改变官方品牌色的含义，例如不能把 ALE Purple 重新定义为错误色。

## 7. 间距、圆角和阴影

采用 4px 基准网格，常用值为 4、8、12、16、24、32、48、64px。

- 图标与文字：8px
- 同组控件：12–16px
- 卡片内边距：16–24px
- 页面区块：32–48px
- 页面上下留白：32–64px
- 小控件圆角：6px
- 输入框、按钮、常规卡片：8–10px
- 大型内容卡片：12–16px

常规卡片优先用边框或极浅阴影；下拉菜单和悬浮面板使用中等阴影；模态框主要依靠遮罩表达层级。同一页面最多使用 2–3 档阴影。

## 8. 页面布局模式

### 8.1 内容或门户型

适用于知识库、培训、产品信息和内容浏览：

```text
顶部栏：Logo | 主导航或搜索 | 用户区
内容区：可选侧栏 | 页面标题、内容、相关内容和下一步
```

### 8.2 应用或工作台型

适用于任务处理、配置管理、记录维护和报表查看：

```text
顶部栏：Logo | 产品名称 | 全局操作
主体区：主导航 | 页面标题、主动作、筛选、工具栏和工作区
```

### 8.3 布局约束

- 内容最大宽度建议 1180–1280px；高密度应用可按任务扩展。
- 文字阅读区不因大屏无限拉宽。
- 顶部栏桌面端 60–64px，小屏端 56–60px。
- 固定侧栏 240–300px，并提供收起能力。
- 页面主要动作通常放在标题区右侧；小屏时移到标题下方。
- 面包屑只表示层级，不用作步骤进度条。

## 9. 响应式与断点

| 断点 | 典型调整 |
|---:|---|
| `≤ 1100px` | 收紧大容器和多列间距 |
| `≤ 980px` | 侧栏转为抽屉或可折叠导航 |
| `≤ 860px` | 双列改为单列，工具栏允许换行 |
| `≤ 640px` | 卡片列表单列，表格自身横向滚动或卡片化 |
| `≤ 560px` | 标题、按钮组和表单纵向布局 |

必须满足：

- 320px CSS 宽度下不出现页面级横向滚动。
- 触控目标建议至少 44×44px。
- 小屏关键内容和操作仍可完成，不能只靠隐藏解决复杂度。
- 200% 浏览器缩放下内容不重叠、不截断。

# 第三部分：核心组件

## 10. 顶部栏与导航

顶部栏包含品牌入口、产品或站点名称、主导航或搜索和用户相关操作。

- 当前项同时使用颜色、字重或标记表达。
- 键盘焦点清晰可见。
- 折叠菜单设置 `aria-expanded`。
- 移动端菜单可关闭，Esc 可退出，焦点不会落到遮罩后。
- Logo 链接的可访问名称表达站点首页。

## 11. 按钮与链接

| 类型 | 用途 | 视觉 |
|---|---|---|
| Primary | 页面最重要的下一步 | ALE Purple 实心、白字 |
| Secondary | 次要操作 | 白底、紫色或中性边框 |
| Tertiary | 低强调操作 | 文字按钮或轻背景 |
| Danger | 删除、撤销发布等高风险操作 | 红色，仅用于危险语义 |

同一可视区通常只有一个主要动作。文案使用动词加对象，例如“创建课程”“保存更改”“导出记录”，避免只有“确定”。

所有按钮实现默认、悬停、键盘焦点、按下、禁用、加载中。

```css
:focus-visible {
  outline: 2px solid #6b489d;
  outline-offset: 2px;
}
```

不要只用低透明度阴影表示焦点。加载按钮保留原宽度。导航使用 `<a>`，当前上下文操作使用 `<button>`，不用可点击 `<div>` 模拟按钮。

## 12. 卡片

- 卡片组织同一主题的信息，不给每段内容都加框。
- 非交互卡片不抬升、不显示手形光标。
- 整卡可点击时提供悬停和焦点状态，并处理内部独立操作。
- 标题层级保持一致；只有并列比较时才强制对齐高度。

## 13. 输入、搜索与筛选

- 可见标签放在控件上方，placeholder 不能替代标签。
- 必填项有明确标记，并解释符号含义。
- 帮助文字说明格式或后果。
- 错误紧邻控件，说明问题和修复方法。

```html
<label for="title">标题</label>
<input id="title" name="title" aria-describedby="title-help title-error"
       aria-invalid="true" />
<p id="title-help">使用能准确描述内容的简短名称。</p>
<p id="title-error" role="alert">请输入标题。</p>
```

搜索应使用 `<form role="search">`，提供标签、结果数量和无结果原因。清除按钮仅在有内容时出现，并设置 `aria-label="清除搜索"`。

活跃筛选条件应可见、可逐个移除。明确筛选是即时更新还是点击“应用”后更新。“重置”只清除筛选，不修改用户数据。

## 14. 表格与数据列表

### 14.1 基础要求

- 使用语义化 `table`、`thead`、`tbody` 和 `th`。
- 表头简短，数字列右对齐，文本列左对齐。
- 表格有空状态、加载状态和错误状态。
- 排序表头使用按钮，并在当前排序列设置 `aria-sort`。
- 行操作靠近行末，常用动作直接显示，低频动作收进菜单。
- 批量操作仅在选择行后出现，并说明已选择数量。

### 14.2 响应式策略

1. **横向滚动**：适合需要比较多列的表格。
2. **优先级隐藏**：小屏显示关键列，其他字段进入详情。
3. **卡片化**：适合记录少、字段语义清晰的列表。

### 14.3 通用示例

| 名称 | 类型 | 状态 | 更新日期 | 操作 |
|---|---|---|---|---|
| 新员工入门 | 课程 | 已发布 | 2026-08-31 | 查看 |
| 品牌资源中心 | 内容集合 | 草稿 | 2026-08-30 | 编辑 |

对象和字段仅演示结构，实际项目应替换为自身业务语言。

## 15. 状态标签

| 语义 | 示例文案 | 图形色（圆点、图标、边框） | 文字与浅底 |
|---|---|---|---|
| Neutral | 草稿、未开始 | `#B9B8B4` | `#616467` 文字、浅灰背景 |
| Info | 进行中、待处理 | `#0085CA` | `#006AA2` 文字、浅蓝背景 |
| Success | 已完成、已发布 | `#00B2A9` | `#007A73` 文字、浅青背景 |
| Warning | 需关注、即将到期 | `#F59E0B` | `#9A4707` 文字、浅橙背景 |
| Danger | 失败、已拒绝 | `#FF4500` | `#A50034` 文字、浅红背景 |

文字一律使用 3.1 表中的深色派生值；官方亮色只用于圆点、图标和边框等图形元素，白底小字号文字禁止直接使用亮色。圆点加文字同现是状态表达最稳的形态。

状态文案应直接、稳定，不使用含义模糊的颜色点。同一状态跨页面使用相同文案和颜色。复杂原因放在邻近文本或详情中。

## 16. 空状态、加载与反馈

### 16.1 空状态

空状态回答三个问题：发生了什么、为什么、下一步做什么。

| 场景 | 标题 | 建议动作 |
|---|---|---|
| 首次使用 | 还没有内容 | 创建第一项 |
| 筛选无结果 | 没有符合条件的结果 | 清除筛选 |
| 搜索无结果 | 未找到相关内容 | 修改关键词 |
| 工作已完成 | 当前没有待处理任务 | 返回全部任务 |

插图为可选项；不要用大插图挤压主要说明和操作。

### 16.2 加载

- 少于约 300ms 的操作通常不显示加载动画，避免闪烁。
- 局部更新使用局部进度，不阻塞整个页面。
- 不确定时长使用旋转指示或骨架屏；可计算时长使用进度条。
- 骨架屏接近最终内容，并设置 `aria-hidden="true"`。
- 更新区域使用 `aria-busy="true"`，完成后改回 `false`。
- 静态文本页面不强制显示骨架屏。

### 16.3 Toast

- 成功反馈简短，例如“更改已保存”。
- 错误反馈说明影响和动作，例如“发布失败，请检查权限后重试”。
- 普通通知使用 `role="status"`；紧急错误使用 `role="alert"`。
- Toast 不应成为唯一错误位置；表单错误仍回到具体字段。
- 关键结果不应过快消失，应允许关闭或保留在页面中。

## 17. 模态框、抽屉与确认

简短确认或少量字段使用模态框；辅助详情或较长表单使用侧边抽屉；复杂、可分享或需要返回的任务使用独立页面。

模态框必须：

- 使用 `role="dialog"` 和 `aria-modal="true"`。
- 通过 `aria-labelledby` 关联标题。
- 打开后把焦点放在合适的首个控件或标题。
- Tab 焦点限制在模态框内；Esc 可关闭非强制流程。
- 关闭后焦点返回触发按钮。
- 遮罩点击是否关闭按误操作风险决定，并在同类组件中保持一致。

危险确认示例：

> 删除“课程草稿”后将无法恢复。已发布内容不受影响。

按钮使用“取消”和“删除草稿”，不要只写“否”和“是”。

## 18. 表单

- 默认单列，标签在控件上方。
- 只有字段关系明确、宽度稳定时才使用双列。
- 长表单按主题分组，提供清晰小标题。
- 主按钮靠近表单末尾；固定底栏只用于很长且频繁保存的表单。
- 能在输入后判断的问题可在失焦时提示，不要每敲一个字符就报错。
- 提交后将焦点移到错误摘要或第一个错误字段。
- 错误摘要能跳转到对应控件。
- 服务端错误保留用户已输入的数据。
- 未保存内容在离开前提示，但不把每次普通导航都变成确认弹窗。

保存后明确告诉用户：保存了什么、当前状态、下一步在哪里。跳转时保持页面标题或面包屑连续。

## 19. 内容、代码与媒体

- 正文容器限制阅读宽度。
- 标题、段落、列表、引用和表格保持稳定垂直节奏。
- 目录只在内容足够长时出现，并标记当前位置。
- 外部链接的新窗口策略保持一致，并给出提示。
- 代码块使用等宽字体和足够对比度，提供复制按钮和成功反馈。
- 长代码行允许代码块自身横向滚动。
- 示例使用明显占位符，不放真实账号、令牌、邮箱或密钥。
- 图片放大层支持 Esc、焦点管理和关闭按钮。
- 图注与图片建立程序化关联。

# 第四部分：数据展示与视觉表达

## 20. 关键数据

关键数据卡片可用于总数、完成率、平均时长、满意度、转化率等通用指标。每张卡片包含指标名称、当前值与单位、对比周期或数据范围，必要时提供趋势和解释。

不要只展示“上升 12%”，还应说明相对哪个时间段或基线。

## 21. 图表

### 21.1 选择图表

| 任务 | 推荐图表 |
|---|---|
| 随时间变化 | 折线图、面积图 |
| 类别比较 | 条形图、柱状图 |
| 构成关系 | 堆叠条形图；类别很少时可用环形图 |
| 分布 | 直方图、箱线图 |
| 目标进度 | 进度条、子弹图 |

避免 3D 图表、装饰性仪表盘和难以比较的多环图。

### 21.2 通用颜色序列

```css
--chart-1: #6b489d;   /* 品牌紫：默认第一序列 */
--chart-2: #0085ca;   /* ALE 蓝 */
--chart-3: #7e5cb4;   /* 紫 500：同族区分 */
--chart-4: #d0006f;   /* 品红：官方扩展色 */
--chart-5: #75787b;   /* 中灰：次要系列与基准 */
--chart-grid: #d9d9d6;
--chart-axis: #616467;
```

- 品牌紫为默认第一序列；类别序列色与状态语义色彻底分离，序列不得取用 3.1 表中的语义派生值。
- 全部序列色在白底上的图形对比度不低于 3:1（本序列实测 4.0–6.9）。
- 低对比官方亮色（如琥珀 `#F59E0B`，白底实测约 2.2:1）不作为序列色；确需使用时只用于大面积填充并配合直接标签。
- 同一数据类别跨页面保持同色。
- 状态色只表达状态，不随类别循环。
- 图例、线型、点形或直接标签至少提供一种非颜色区分方式。
- 图表文字和网格线满足对比度要求。

### 21.3 可访问替代

- 图表有标题和一句话摘要。
- 关键结论不能只存在于图形中。
- 复杂图表提供数据表或可下载数据。
- 交互提示不能只依赖鼠标悬停，键盘和触摸也可访问。

## 22. 日期、数字与单位

- 日期格式在同一产品内统一；国际化产品按 locale 格式化。
- 相对时间用于近期浏览；精确时间可通过详情或 tooltip 查看。
- 数值列使用千位分隔和一致小数位。
- 百分比明确分母和统计口径。
- 时长按尺度显示秒、分钟、小时或天。
- 金额显示币种，并按 locale 处理小数和分隔符。
- 不在单位和数值之间随意换行。

# 第五部分：无障碍、动效与系统状态

## 23. 无障碍基线

正式项目至少满足 WCAG 2.2 AA 的核心要求：

- 普通文字对比度至少 4.5:1；大文字至少 3:1。
- 键盘可完成所有操作，焦点顺序符合视觉顺序。
- 焦点持续可见，不被 sticky 区域或弹层遮挡。
- 页面有唯一明确的 `h1`；标题层级连续。
- 表单控件有程序化名称，错误与帮助文字正确关联。
- 跳转链接允许键盘用户直接进入主要内容。
- 页面语言设置正确，例如 `<html lang="zh-CN">`。
- 状态更新通过合适的 live region 通知辅助技术。
- 目标尺寸、拖拽替代和认证流程按 WCAG 2.2 评估。

## 24. 动效

- 微交互：120–180ms
- 面板、菜单、模态框：180–260ms
- 使用标准缓动，避免弹跳和长时间连续动画
- 优先动画 `transform` 和 `opacity`

必须尊重减少动态效果设置：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

减少动效后，状态变化仍应清楚。

## 25. 系统状态与错误页

系统需要覆盖：

- 无权限：说明不能访问什么，并提供返回或申请权限路径。
- 内容不存在：说明内容可能被移动或删除，提供搜索或返回入口。
- 连接中断：保留用户输入，允许重试。
- 服务暂时不可用：说明这是暂时问题，不暴露技术堆栈。
- 会话过期：解释需要重新登录，并在安全前提下恢复上下文。

错误信息公式：

> 发生了什么 + 对用户造成什么影响 + 用户现在能做什么

不要只显示错误代码。诊断编号放在次要位置并支持复制。

# 第六部分：工程实现

## 26. 推荐样式架构

```text
styles/
├─ tokens.css       # 基础、语义和组件令牌
├─ reset.css        # 最小化浏览器差异
├─ base.css         # 字体、正文、链接、焦点
├─ layout.css       # 容器、栅格、页面骨架
├─ components.css   # 按钮、表单、卡片、表格等
├─ content.css      # Markdown 或长文内容
└─ utilities.css    # 少量、明确的工具类
```

如果使用 CSS Modules、Vue scoped CSS、Tailwind 或 CSS-in-JS，仍应保留同样的令牌层级和组件状态，不要把技术框架的默认主题当作 ALE 品牌规范。

## 27. 组件 API 约束

通用组件优先暴露语义，而不是视觉细节。

推荐：

```text
Button: variant=primary|secondary|tertiary|danger
        size=sm|md|lg
        loading=true|false

Alert:  tone=info|success|warning|danger
Badge:  tone=neutral|info|success|warning|danger
```

不推荐：

```text
Button: purple=true, rounded=12, shadow=medium
```

语义 API 能保证跨项目一致并允许主题升级；视觉拼装参数会让组件逐渐失控。

## 28. 层级与 z-index

禁止随意使用 `9999`：

| 层级 | 建议值 |
|---|---:|
| 页面内容 | 0 |
| Sticky 顶栏或局部工具栏 | 100 |
| 下拉菜单、Popover | 300 |
| 抽屉、模态框遮罩 | 500 |
| 模态框内容 | 510 |
| Toast | 700 |
| 全局阻断提示 | 900 |

通过 portal 或统一浮层根节点管理弹层，避免父级 `transform` 或 `overflow` 造成层叠问题。

## 29. 性能与稳定性

- 首屏只加载当前页面必要资源。
- 图片提供明确宽高，减少布局偏移，并按展示尺寸压缩。
- 字体失败时使用可靠回退，不阻塞文字显示。
- 大列表使用分页、增量加载或虚拟化，同时保留键盘和辅助技术可用性。
- 动画不持续占用主线程。
- 组件在慢请求、空数据、超长文字、多语言和错误响应下结构稳定。

## 30. 框架映射说明

React、Vue、Angular、Web Components 或服务端模板都可以实现本规范。框架选择属于工程决策，不属于 ALE 品牌要求。

Lucide 等线性图标库可作为推荐选择，但项目必须统一，不混用多套图标。使用工具类框架时，应先把本规范令牌映射到主题配置，再构建组件；不要长期复制任意颜色和间距值。

## 32. 页面验收清单

### 32.1 品牌

- [ ] 使用官方 Logo 资产，比例、颜色和安全空间正确
- [ ] 首次公司名称写作 Alcatel-Lucent Enterprise

### 32.2 结构与视觉

- [ ] 页面只有一个清晰的主目标和主要动作
- [ ] 标题层级连续，正文默认不小于 16px
- [ ] 间距使用令牌，没有大量任意数值
- [ ] 非交互卡片没有虚假悬停反馈
- [ ] 状态不只依赖颜色表达

### 32.3 交互

- [ ] 控件覆盖默认、悬停、焦点、按下、禁用和加载状态
- [ ] 链接负责导航，按钮负责操作
- [ ] 表单错误指出原因和修复方法
- [ ] 危险操作说明对象、影响和可恢复性

### 32.5 内容和数据

- [ ] 日期、数值、单位和状态文案在产品内统一
- [ ] 图表有标题、摘要和非颜色区分方式
- [ ] 表格排序正确设置 `aria-sort`
- [ ] 超长标题、空值和多语言不会破坏布局
- [ ] 示例和文档不包含真实凭据或个人数据

## 33. 建议验收流程

1. **品牌检查**：核对 Logo、名称、官方色和法律信息。
2. **设计令牌检查**：确认颜色、间距、字体和层级来自令牌。
3. **组件状态检查**：验证按钮、表单、卡片、表格和弹层状态。
4. **响应式检查**：检查 320、768、1024、1440px 和 200% 缩放。
5. **无障碍检查**：运行自动化工具，再进行键盘、焦点和读屏人工检查。
6. **内容压力测试**：使用空内容、长文本、多语言、大数字和失败响应。
7. **跨浏览器检查**：覆盖项目支持矩阵中的浏览器和操作系统。

自动化工具只能发现一部分问题，不能替代人工检查。

## 34. 版本治理

- 主版本号表达不兼容变化，次版本号表达新增规则，修订号表达勘误。
- 项目级偏离应记录原因、负责人、影响范围和复审日期。
- 新组件先验证是否能由现有模式组合，确认不能后再进入通用组件库。
- 颜色、状态词和交互模式变更应同步更新设计资源、代码令牌和文档。
- 每次重大版本发布抽查至少一个内容型页面和一个应用型页面，防止规范只适合单一产品形态。

## 附录 D：官方品牌硬规则（依据 September 2025 版指南）

本附录收录官方品牌指南中可直接执行的事实规则。项目层主题与本附录冲突时，以本附录为准。

### D.1 品牌色与色调档位

- 主紫 **Pantone 267C**：C70 M85 Y0 K0 / R107 G72 B157 / `#6B489D`。

### D.3 命名组合

产品命名组合中**品牌在前**：Alcatel-Lucent Enterprise 名称与 brandmark 在前，产品名或描述词置于末尾（指南 NAMING COMPOSITION 原则："the brand goes first"）。公司名首次出现写全称 **Alcatel-Lucent Enterprise**，后续可缩写 ALE。
